Layered System Architecture & Class Hierarchy

Designed strictly using Object-Oriented principles, separation of concerns, and clean encapsulation.

Presentation Layer

Console & UI Classes

PatientMenu.java Terminal UI for appointment request, status inquiry, and viewing medical records.
DoctorMenu.java Terminal UI for review queue, decision making, and recording consultations.
InputHelper.java Validated console parsing for integers, strings, and dd-MM-yyyy HH:mm dates.
Business Logic Layer

Service Controllers

AppointmentService.java Enforces past-date validation, creates initial PENDING requests, handles approval decisions.
ConsultationService.java Verifies APPROVED status, records diagnosis/Rx, and orchestrates automatic follow-up booking.
Domain Entities

Core Models & Enums

Appointment.java Stateful entity containing Patient, Doctor, LocalDateTime, AppointmentStatus, followUp flag.
Consultation.java Clinical record linking appointment, diagnosis text, prescription notes, next visit date.
AppointmentStatus.java Enum: PENDING, APPROVED, REJECTED.
Patient.java & Doctor.java Encapsulated entities for system actors with unique identifiers and contact/specialty details.
Data & Safety

Repository & Exceptions

InMemoryRepository.java Thread-safe collections storage using HashMap, LinkedHashMap, and ArrayList.
InvalidInputException.java Custom unchecked exception for past dates, empty strings, and malformed inputs.
InvalidStateException.java Custom exception preventing illegal transitions (e.g. deciding approved appointments).

Teacher Viva & Evaluation Oral Questions

Quick reference answers for teacher evaluations and laboratory assessments.

Q1. What is the core workflow and main problem solved by this project? ▼

The system connects appointment requesting, doctor approval, clinical consultation recording, and automatic follow-up booking into a single coherent lifecycle. It eliminates manual follow-up scheduling errors by automatically creating an APPROVED follow-up appointment when the doctor inputs the next-visit date.

Q2. Why is in-memory storage used instead of a relational database like MySQL? ▼

In accordance with Core Java course guidelines, using in-memory Java Collections (HashMap, LinkedHashMap, ArrayList) demonstrates mastery of data structures, references, and memory management without introducing external driver dependencies.

Q3. Why is the automatic follow-up appointment created with status APPROVED? ▼

Because the doctor themselves evaluated the patient in the consultation room and established the medical need for a follow-up on that specific date. Therefore, it does not require a second doctor approval step and is directly booked as APPROVED.

Q4. How do you prevent an appointment from being approved multiple times? ▼

In Appointment.updateDecision(), we check if (status != AppointmentStatus.PENDING). If someone tries to approve an already approved or rejected appointment, it immediately raises an InvalidStateException.

Q5. How is separation of concerns achieved in this application? ▼

The code is divided into four distinct layers: UI handles input/output; Service validates and executes business rules; Repository manages data structures; and Model encapsulates properties. This allows swapping the console UI for a Web UI or GUI without changing any business logic.
