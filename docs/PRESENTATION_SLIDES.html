5-Stage Clinical Lifecycle Pipeline
Deterministic state machine transitions preventing invalid workflows

1. Request

Patient selects practitioner and submits preferred date/time. Initial state: PENDING.

2. Decisioning

Doctor approves or rejects with clinical audit justification. Transitions to APPROVED / REJECTED.

3. Consultation

Doctor records diagnosis & prescription. System verifies visit was approved and not duplicate.

4. Auto Follow-Up

Doctor enters next visit date -> system automatically books follow-up with status APPROVED.

5. Billing & Invoicing

Itemized medical bill generated (Doctor fee + 5% Healthcare GST). Exported to records/invoices/.

6. Digital Rx Slip

Official clinical discharge slip with digital cryptographic verification hash saved to disk.

Object-Oriented Design & SOLID Principles
Applying foundational design patterns without external framework bloat

Polymorphic Domain Abstraction

Abstract base class Person extended by Patient and Doctor.

Person p = doctor; System.out.println(p.getRole()); // "DOCTOR" System.out.println(p.getSummaryDetails()); // Dynamic dispatch

Dependency Inversion Principle (DIP)

Services depend strictly on the IDataRepository interface rather than concrete in-memory collections, ensuring modularity.

public class AppointmentService { private final IDataRepository repo; // Decoupled from physical storage implementation }
Concurrency & Zero-Dependency Persistence
Production-grade safety under concurrent multi-threaded execution

Thread-Safety & Race Condition Immunity

  • AtomicInteger for lock-free sequence ID generation (verified in TC-16 under 10 parallel threads).
  • ConcurrentHashMap for high-concurrency patient/doctor queries.
  • Collections.synchronizedMap for order-preserving appointment queues.

Graceful Shutdown & Snapshot Engine

  • FilePersistenceService serializes database snapshots without SQL drivers.
  • Runtime.getRuntime().addShutdownHook(...) ensures state is automatically saved even if terminated via Ctrl+C.
