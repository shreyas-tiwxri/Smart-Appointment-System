Abstract

In outpatient clinical facilities and polyclinics, manual scheduling, decentralized prescription storage, and disconnected follow-up scheduling lead to operational errors including doctor double-booking, treatment delays, and untracked billing discrepancies. The Doctor Smart Appointment & Clinical Workflow System is an enterprise-grade Core Java application engineered to automate the complete outpatient consultation lifecycle from booking to discharge.

The system implements a decoupled 4-tier layered architecture adhering to Object-Oriented Programming (OOP) and SOLID principles, completely free from external third-party frameworks. Key architectural components include:

  • Polymorphic Domain Hierarchy: Abstract class Person extended by concrete actors Patient and Doctor using dynamic method dispatch.
  • Interface-Driven Repository: IDataRepository implemented by InMemoryRepository using ConcurrentHashMap and AtomicInteger to ensure race condition immunity during concurrent access.
  • 30-Minute Slot Collision Prevention: Automated verification checking doctor availability within a 30-minute consultation window using java.time.Duration.
  • Consultation & Automated Follow-Up Engine: Automatically generates an APPROVED follow-up visit based on the doctor's review timeline, generates official medical invoices with 5% Healthcare GST, and creates digital prescription slips with cryptographic verification hashes.
  • Decoupled Observer Notifications: Real-time alert engine delivering asynchronous event updates to patients and doctors.
  • Dual User Interface: Interactive ANSI-colored command-line interface (CLI) coupled with a 100% Core Java Swing multi-tab desktop application (MainWindow.java).
  • Zero-Loss JVM Shutdown Hook: Automatic disk snapshotting to flat files on application termination.

The software was rigorously validated against a self-contained 20-scenario automated verification test suite (SystemWorkflowTest.java) covering unit logic, slot conflict guards, and multi-threaded race conditions, achieving a 100% pass rate.

Chapter 1: Introduction

1.1 Introduction to the Project

Outpatient clinical departments face frequent administrative and operational bottlenecks during doctor-patient coordination. The traditional approach of maintaining manual paper registers, standalone spreadsheets, or fragmented local apps introduces scheduling overlaps, untracked appointment cancellations, manual calculation mistakes during billing, and uncoordinated follow-up treatments.

The Doctor Smart Appointment & Clinical Workflow System is a standalone Core Java desktop and console coordination application developed to manage the entire outpatient consultation pipeline. Engineered using Java SE 17+, the project adheres strictly to Object-Oriented Analysis and Design (OOAD) principles without relying on third-party frameworks like Spring or external database drivers. It coordinates patient appointment requests, doctor review queues, slot conflict guards, diagnosis entry, automated follow-up booking, medical invoicing, and flat-file disk persistence.

1.2 Problem Statement

Clinical facilities without unified scheduling software encounter four recurring challenges:

  1. Schedule Collisions & Double-Booking: When patients request visits without automated collision validation, practitioners receive overlapping appointments for the same hour, causing extended waiting times and clinic congestion.
  2. Disconnected Follow-Up Scheduling: When a practitioner advises a patient to return in 14 days, the manual booking must be separately scheduled by reception, frequently resulting in forgotten reviews or slot unavailability.
  3. Manual Billing Inaccuracies: Manually applying consultation rates, calculating healthcare GST, and printing receipts is time-consuming and prone to arithmetic mistakes.
  4. Data Fragility on Abrupt Exit: In-memory applications risk total state loss if an abrupt shutdown or terminal closure occurs before state is explicitly committed.

1.3 Objectives of the Project

  • Pure Core Java Architecture: Implement all data structures, services, UI interfaces, and testing frameworks relying exclusively on standard JDK libraries.
  • Automated 30-Minute Slot Collision Guard: Build a schedule validation algorithm preventing overlapping doctor appointments within a 30-minute window.
  • Automated Follow-Up Scheduling: Automatically generate an APPROVED follow-up appointment upon consultation completion.
  • Medical Invoicing & Healthcare GST: Automatically compute specialist consultation charges, add 5% healthcare GST, and generate formatted receipts.
  • Thread-Safe Concurrency: Utilize ConcurrentHashMap and AtomicInteger to guarantee race condition immunity under multi-threaded operations.
  • Dual User Interface: Provide an interactive terminal CLI alongside a full-featured desktop GUI built with 100% Core Java Swing.
  • 100% Test Coverage: Create a custom 20-test automated verification suite validating all domain rules without external test runners.

1.4 Scope of the Project

The scope encompasses outpatient appointment lifecycle management (PENDING, APPROVED, REJECTED, CANCELLED), doctor analytics, local disk persistence for prescriptions (records/prescriptions/) and invoices (records/invoices/), and automated state snapshotting via JVM shutdown hooks. Network-based payment gateway APIs and cloud-distributed database replication are outside the scope of this Core Java laboratory project.

2.2 Use Case Diagram & Actor Descriptions

The system defines three primary actors:

  • Patient: Submits appointment requests, views scheduled appointments, reviews clinical prescriptions, and cancels or reschedules upcoming visits.
  • Doctor: Inspects pending queues, approves or rejects appointments with mandatory clinical audit reasons, conducts consultations, records diagnoses and prescriptions, and views workload analytics.
  • Automated System Engine: Enforces 30-minute slot buffers, auto-schedules follow-up visits, computes GST, logs audit trails, and exports state snapshots.

2.5 Database & In-Memory Data Structure Design

The persistence model uses thread-safe in-memory collections paired with automated file snapshotting:

  • ConcurrentHashMap<Integer, Patient> and ConcurrentHashMap<Integer, Doctor>: High-speed O(1) indexed entity storage.
  • ConcurrentHashMap<Integer, Appointment>: Thread-safe appointment record store.
  • Collections.synchronizedList(new ArrayList<>()): Preserves chronological order for audit logs and UI display.
  • AtomicInteger primary key sequences (nextAppointmentId, etc.): Lock-free atomic increment counters.

3.4 Implementation of Major Modules

3.4.1 30-Minute Slot Collision Detection

The collision guard inspects existing active appointments for the chosen practitioner and verifies that no active booking exists within 30 minutes: 

public void checkSlotAvailability(int doctorId, LocalDateTime dateTime, int excludeApptId) {
    Doctor d = repo.getDoctor(doctorId);
    for (Appointment existing : repo.getAllAppointments()) {
        if (existing.getAppointmentId() == excludeApptId) continue;
        if (existing.getDoctor().getDoctorId() != doctorId) continue;
        if (existing.getStatus() != AppointmentStatus.PENDING && 
            existing.getStatus() != AppointmentStatus.APPROVED) continue;

        long minuteDiff = Math.abs(Duration.between(existing.getDateTime(), dateTime).toMinutes());
        if (minuteDiff < Config.SLOT_BUFFER_MINUTES) {
            throw new InvalidStateException(String.format(
                "Slot Conflict: Dr. %s already has an active appointment (#%d at %s). A %d-minute consultation buffer is required.",
                d.getName(), existing.getAppointmentId(), existing.getDateTime().format(FMT), Config.SLOT_BUFFER_MINUTES));
        }
    }
}

3.5 Exception Handling Hierarchy

The application implements custom unchecked exceptions extending RuntimeException:

  • InvalidInputException: Thrown when date parsing fails, inputs are blank, or past appointment timestamps are entered.
  • InvalidStateException: Thrown on invalid state transitions (e.g., approving an already finalized appointment, scheduling conflicting slots within 30 minutes, or recording duplicate consultations).
  • NotFoundException: Thrown when an ID lookup fails.

3.6 Collection Framework & Concurrency Usage

  • ConcurrentHashMap: Provides lock-striped thread-safe read/write operations without locking the entire storage structure.
  • AtomicInteger: Ensures thread-safe sequential primary key increments under multi-threaded concurrency.
  • Collections.synchronizedList: Preserves insertion order for UI tables and file snapshotting.

3.7 Data Persistence & File Management

The persistence module writes records to flat files:

  • Prescriptions: Stored in records/prescriptions/Rx_Patient<X>_Appt<Y>.txt with verification hashes.
  • Invoices: Stored in records/invoices/INV-2026-XXXX_Patient<X>.txt.
  • Database Snapshots: Written to records/database_snapshot.txt via JVM shutdown hook.
